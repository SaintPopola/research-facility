Every competitor ships a browser complaint (Serum 2 "woeful", Vital "name-search-only", Omnisphere "14k you'll scroll past", Pigments "browsing fatigue", FabFilter "no discovery at all"): the entire market's #1 documented weakness is exactly RF's home turf. Wrap it in the trust package that is the single most-praised business decision across every thread: buy once, lifetime updates, no license server, no account, no phone-home, GPL repo = public roadmap. ## Phased plan

**Ships:** Same features, but nothing clicks, every knob is smoothed/tooltipped/MIDI-learnable, UI scales crisp to fullscreen, macros transform the patch musically, and the store leads with a benchmark + a licensing promise no rival can match. RF now FEELS like a $79 plugin.

- Zipper-free smoothing GLOBALLY: route every macro→DSP connection through a scriptnode smoothed_parameter/ramp node (0.02-0.05s), on the audio thread not a UI timer. Verify by sweeping cutoff at max speed on a scope = zero zipper.
- Workflow-parity checklist (reviewers dock for ANY missing): fully resizable VECTOR UI (paint routines/scalable ScriptPanels — commit vector-first NOW, retrofitting is a rewrite), A/B compare (2 ValueTree snapshot slots), plugin-internal undo/redo, MIDI Learn on every knob, hover tooltip (one plain-language line per control, FabFilter-style).
- Rewrite the 6 macros as PERCEPTUAL vibe-words (Air/Body/Motion/Space/Grit/Width). Each fans out to 2-5 DSP params via hand-drawn Table curves (Pro-R 'Space links decay+size' model). Clamp ranges so every macro always sounds good (Portal trick). Never show raw DSP names on the front panel.
- Publish honest per-voice CPU + max-instance benchmark on the storefront (sample-streaming + one filter is inherently 10x lighter than Pigments/Serum). 'Runs 100+ voices on a laptop on battery' is a real quotable claim against the market's loudest complaint.
- Ship the trust copy above the fold: 'No license server. No account. No phone-home. Perpetual means perpetual. Buy once, lifetime updates. An OS update will never brick your instrument. GPL core.' Point every anti-WUP / anti-ASC / anti-Output-Trustpilot resentment straight at this.

### Phase 1 — The sound: one great character filter (2-3 wks) — Pigments' entire redemption was 'add the MS-20 filter, it stopped being sterile.' This is the highest-ROI DSP work in the whole competitive set. Do it before ANY new engine.

**Ships:** The existing 53 specimens now sound alive and analog through a filter that carries character, with per-voice drift and a Clean/Tape/Tube color. RF crosses from 'sample player' to 'instrument with a sound' — the single biggest perceptual leap available.

- Build a 2-3 model character filter in scriptnode: ladder + SEM/state-variable + a driven Rage/diode mode, exposed via a switch. Drive input with a waveshaper/saturation node + pre/post gain for the diode flavor; small feedback graph for self-oscillation character.
- For genuine ZDF (beat Vital's 'steppy at high resonance'): drop published Faust ZDF ladder/SVF DSP into a HISE Faust node rather than relying on the stock filter alone. Studio bar = the filter alone makes a static specimen sound expensive, smooth click-free resonance sweeps, musical self-oscillation.
- Add an oversample container around ONLY the nonlinear nodes (waveshaper/driven filter), 2x/4x default with a per-patch HD switch (off/2x/4x, 16x for mastering). Label the CPU cost — dodge Vital's 'unpredictable per-preset oversampling' gripe. Init at 1x and switch up at runtime (known Windows 4x-init crash).
- Per-voice drift/humanization (Pigments Voice Modulator): per-voice seeded random modulator adding tiny pitch/filter/level offsets. Cheap DSP, outsized 'analog feel', directly attacks the 53-static-samples 'sterile ROMpler' risk.
- One 'Character' output dropdown: Clean/Tape/Tube = waveshaper node + subtle drift on the output bus. FabFilter retrofitting Character into Q4/C3/R2 proves the market demands switchable color on clean engines.

## HISE hard truths to plan around

- AAX requires becoming a registered Avid developer to sign. You canNOT ship an AAX plugin Pro Tools will load without signing via PACE/wraptool. Good news: registering as an Avid developer gets you a PACE EDEN Tools signing license for FREE (no separate PACE purchase). Without a Pro Tools Developer license you can't even preview unsigned — so factor the Avid registration into the AAX timeline, and verify the AAX SDK version matches HISE 4.1.0 (forum has a specific thread on which SDK version works — check it before compiling).
- scriptnode has NO native wavetable node. Wavetable synthesis MUST go through the built-in WavetableSynthesiser module, so you cannot build a fully custom wavetable engine as a scriptnode graph — you customize via the WavetableController + offline table generation, not by wiring nodes.
- Matching Serum/Vital OSCILLATOR cleanliness at extreme wavetable-position modulation is a paid-DSP-contractor problem, not a scripting problem. HISE's author states Serum 'paid a couple thousand dollars' for their oscillator math; HISE's built-in is 'industry-standard' but not Serum-tier at the edges. Plan: ship a solid layer now, budget a C++/SNEX DSP contractor if you truly need Serum parity later. Don't block launch on it.
- Oversampling caps at 16x (not FabFilter's 32x) — fine (16x is the practical ceiling per HISE's author) but spec it honestly. Also a known bug: the scriptnode oversample node has crashed when initialized directly at 4x on some Windows machines — initialize at 1x and switch up at runtime, and test on Windows before release.
- The granulator node is officially prototype-stage and the HISE author has said it may be redesigned / moved out of core into a SNEX example. Don't build a flagship granular engine on the stock node expecting API stability — fork the SNEX granular source into your own SNEX node so a HISE update can't break you. Also: the granulator distributes grains across held notes rather than true polyphonic voices (by design) — fine for pads, not for polyphonic granular leads.
- HISE runs NO ML model at runtime — CLAP embedding and any text encoder are NOT native. All embeddings must be precomputed offline in Python and shipped as data. 'More like this' (cosine similarity on stored 512-dim vectors) is trivial in-plugin; free-text 'type ANY vibe' needs a text encoder, which means either (a) precomputing embeddings for a fixed curated tag/mood vocabulary (ship v1 this way) or (b) bridging a small quantized ONNX text encoder via an external process / custom C++ node (v2). Don't promise open-ended free-text search until the encoder bridge is proven.
- HISE's stock compressor and EQ are usable but NOT Pro-C/Pro-Q-tier. Do not position RF's FX as beating FabFilter on FabFilter's turf. RF's winnable FX axes are (1) convolution reverb with curated real-room 'specimen' IRs and (2) an oversampled character/saturation stage — both fit the curation brand. Compete on discovery + curation + ownership, not on out-compressing Pro-C.
- MPE is a genuine HISE strength, but per-voice modulation and audio-rate modulation have caveats: audio-RATE modulation (Vital's 20Hz–20kHz mod) requires routing the modulator as an audio signal inside scriptnode, not as a control-rate HISE modulator — it's doable but is real DSP-graph work, not a checkbox. Control-rate LFO/env/macro modulation is easy and covers 90% of use cases; save audio-rate FM-style mod for a later milestone.
- Resizable UI must be built vector-first (paint routines / scalable ScriptPanels), NOT fixed bitmaps. Bitmap UIs are exactly why Waves' catalog 'looks dated' and blur when scaled. This is a discipline/architecture decision you must commit to at the START of UI work — retrofitting vector rendering onto a bitmap UI is a rewrite.
- Solo/tiny-team bus-factor and ship-quality: Serum 2 launched with crash bugs and needed a year of fixes; goodwill only absorbed it because of the free-lifetime-update promise. RF should copy that promise verbatim ('buy once, lifetime updates, no license server') because it's cheap for a new brand and is the single most-praised business decision across every competitor thread — AND publish the GPL repo commit history as the public roadmap proof, since visible open development is the direct antidote to the abandonware anxiety that dogs Vital (solo dev) and Output (Trustpilot).
